# 어느 층의 풍경

엘리베이터 안에서 문 너머 아홉 가지 도트 풍경을 만나는 모바일 크기 웹앱입니다. 기존 노을 바다에 모닥불, 비 오는 정원, 고양이, 수족관, 반딧불이 숲, 눈 내리는 산장, 계곡, 꽃밭을 추가했습니다. 탑승하는 사람은 없습니다.

## 실행과 미리보기

```sh
npm ci
npm run dev
npm test
npm run build
```

- 본 화면: http://127.0.0.1:5174/
- 아홉 장면 동시 애니메이션 비교: http://127.0.0.1:5174/animated.html
- 비교 화면에서는 ‘엘리베이터 안에서’ / ‘풍경만 보기’를 바꿀 수 있습니다. 소리는 재생하지 않습니다.
- 현재 작업 공간은 이전 프로젝트의 node_modules를 연결해서 사용합니다. 별도 폴더에서는 npm ci로 설치합니다.
- Vite의 상대 base 경로와 두 HTML 진입점을 설정했습니다. dist 폴더를 정적 호스팅에 올리면 본 화면과 비교 화면 모두 동작합니다. GitHub Pages에서는 gh-pages 브랜치의 빌드 결과를 서비스합니다.

## 운행

본 화면에는 자동운행 ON/OFF 스위치 하나만 있습니다. 처음에는 OFF이고, ON을 누르면 실제 엘리베이터 음원과 문이 함께 움직입니다.

| 음원 위치 | 동작 |
|---|---|
| 0~4초 | 도착, 약 1초에 띵 소리 |
| 4~8초 | 문이 양 끝에서는 천천히, 중간에서는 빠르게 열림, 이미 움직이던 풍경이 드러남 |
| 8~12초 | 문이 완전히 열린 상태 |
| 12~16초 | 양 끝에서는 천천히, 중간에서는 빠르게 문 닫힘 |
| 16초~21.168초 | 닫힌 상태에서 다음 목적지를 준비 |

OFF를 눌렀을 때 이미 문이 열리는 중이면 그 방문의 감상·닫힘을 원래 시간대로 마친 뒤 대기합니다. 즉시 닫거나 음원 시간을 건너뛰지 않습니다. 문이 닫혀 있으면 다음 열림 없이 대기합니다. 다시 ON을 누르면 새 운행을 시작하며, 아직 이전 방문을 마치는 중이라면 시간 점프 없이 자동운행을 이어갑니다.

첫 방문은 모닥불입니다. 다음 목적지는 아직 보지 않은 곳부터 무작위로 선택하고, 같은 장소가 연속으로 나오지 않습니다. 첫 아홉 번의 방문에서 모든 장소를 볼 수 있습니다. 풍경은 반드시 문이 닫혀 있을 때 바뀝니다. 탭이 오래 비활성화되어 닫힘 시점을 놓친 경우에도, 문이 열려 있는 동안에는 현재 풍경을 유지합니다.

## 애니메이션 구성

각 장소는 2×2 비트맵 스프라이트 시트의 네 프레임을 사용합니다. 서로 다른 속도로 A-B-C-D-C-B를 연결하고, 프레임 사이를 보간합니다. 환경 시계는 음원·문 시계와 독립적으로 흘러서 문을 열 때 애니메이션이 처음부터 다시 시작되지 않습니다. 렌더링은 최대 30fps입니다.

| 장소 | 움직임 |
|---|---|
| 노을 바다 | 파도 프레임, 수면 흐름과 반사광 |
| 숲속 모닥불 | 불꽃 모양과 떠오르는 불씨 |
| 비 오는 정원 | 물웅덩이 잔물결, 떨어지는 빗방울 |
| 햇볕 아래 고양이 | 미세한 숨결, 귀와 꼬리 포즈, 햇빛 속 작은 먼지 |
| 수족관 전시실 | 물고기와 해파리 포즈, 유리 수조 안의 기포 |
| 반딧불이 숲 | 반딧불이의 위치·밝기 변화와 독립적인 비행 |
| 눈 내리는 산장 | 굴뚝 연기와 서로 다른 속도로 내리는 눈 |
| 계곡 | 폭포의 포말과 수면 반사 |
| 바람 부는 꽃밭 | 꽃의 바람 포즈와 두 마리 나비 |

각 장면의 움직이는 영역을 마스크로 분리합니다. 기본 프레임 위에 해당 영역만 합성해서 길·바위·건축물·객실이 통째로 흔들리지 않게 합니다. 불꽃·반딧불이·물결은 색상 조건도 함께 사용합니다. 원본 스프라이트를 256px 프레임으로 한 번 준비하여 재사용하고, 큰 이미지 디코딩은 두 장씩 제한합니다.

객실은 256×320 논리 픽셀, 표시 크기는 최대 390×487.5px입니다. PC에서도 같은 크기를 유지하며 작은 모바일 화면에서는 축소합니다. 원화 비율을 늘이지 않고 엘리베이터 문에 맞게 좌우만 잘라 표시합니다. 문은 고정 크기 패널을 정수 픽셀 단위로 이동합니다.

## 주요 파일

- src/destinations.ts: 장소 목록, 스프라이트 파일, 프레임 간격.
- src/environment.ts: 스프라이트 준비, 움직임 마스크, 장면별 파티클과 합성.
- src/DestinationRotation.ts: 목적지 순서와 닫힌 문 뒤에서의 전환.
- src/renderer.ts: 객실·문·배경 합성.
- src/Playback.ts, src/timeline.ts: 실제 음원 기준 운행과 문 시간.
- src/AnimationPreview.tsx, animated.html: 아홉 장면을 한 번에 비교하는 별도 화면.
- public/assets/*-sprites.png: 장소별 네 프레임 원화.
- ANIMATION_PROMPTS.json: 추가한 여덟 장면의 정확한 생성 프롬프트 및 참조 시안 경로. 내장 ImageGen으로 제작했으며 CLI/API 생성은 사용하지 않았습니다.
- previews/: 이전 검토용 정지 시안. 실제 앱은 public/assets의 스프라이트를 사용합니다.

사용자가 제공한 freesound_community-elevator-ding-door-open-close-noisy-10-62069.mp3를 public/assets/elevator-cycle.mp3로 원본 그대로 사용합니다. 길이는 약 21.168초, 볼륨은 원본의 55%이며 새 환경 음원을 추가하지 않았습니다.

## 검증

- 자동 테스트 47개: 운행 ON/OFF, 문 시간, 프레임 연속성, 모든 스프라이트 파일의 실제 형식/격자, 닫힌 문 뒤에서만 전환, 전체 목적지 방문 및 연속 중복 방지.
- TypeScript와 Vite 프로덕션 빌드.
- 실제 Chrome에서 아홉 장면 표시와 프레임 진행, 시간차 화면 캡처의 배경 픽셀 변화 및 객실 픽셀 고정 확인.
- 390×844 모바일 크기에서 장면 358×447.5px, 가로 넘침 없음. 실제 운행의 목적지 전환 및 열리는 중 OFF 후 현재 방문을 마치는 상태 확인.

## 배포

소스는 main 브랜치, 정적 빌드 결과는 gh-pages 브랜치로 분리합니다. GitHub Pages의 소스는 gh-pages / (root)로 설정합니다.

```sh
npm test
git add .
git commit -m "Update elevator garden"
git push origin main
npm run deploy
```

npm run deploy는 로컬에서 빌드한 뒤 임시 Git 저장소를 통해 gh-pages에 새 커밋을 추가합니다. 강제 푸시를 하지 않으며 기존 배포 이력을 보존합니다. GitHub 인증이 설정된 환경에서 실행합니다.
